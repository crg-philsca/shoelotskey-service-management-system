1. Audit Findings: Verification of the Reported Rule-Based Baseline

A. Code Inspection & Root Cause Analysis

Direct code inspection of the generation script (generate_dataset_b.py) and evaluation pipelines reveals that the previously reported Rule-Based Baseline (MAE = 0.1967 days, RMSE = 0.5825 days, R² = 0.9950) used only the shop's base service tiers and the 1-day rush override (rule_base_days).

Summary of Implemented Rules in Base-Tier Baseline:
  • Tier Hierarchy: 25 days (FR / COR), 20 days (MRES / UNY), 10 days (MR / BC).
  • Rush Override: 1 day if Basic Cleaning only, rush=1, and pairs ≤ 3.
  • Omitted: Sunday closures (+1 day rollover) and statutory holidays (Holy Week, Christmas, New Year).

Because the generator added 295 total rollover days across 240 affected orders in the 1,500 test set (mean rollover = 295 / 1500 = 0.19667 days), the base-tier prediction under-predicted by exactly that amount, resulting in an exact MAE of 0.1967 days and a constant negative bias of -0.1967 days.

B. Dual Baseline Formulation & Resolution

To maintain rigorous academic transparency and satisfy methodological guidelines, the evaluation was restructured to report two distinct, precisely defined rule-based baselines:

1. Base-Tier Rule Baseline (Static Service SLA):

Reflects standard heuristic shop practice where turnaround promises are fixed by service category (1, 10, 20, 25 days) without calendar lookup. Evaluated MAE: 0.1967 days.

2. Complete Generator-Derived Rule Baseline:

Implements the full deterministic business logic available at intake (service tiers, rush override, Sunday closures, and statutory holiday lookup). Because the simulation engine contained no stochastic noise, this baseline achieves: MAE = 0.0000 days, R² = 1.0000.

✓ Leakage Guard Enforced: All rule baseline predictions were computed dynamically from input features (service quantities, total pairs, rush indicator, intake date) without reading any target-derived columns.

3. Critical Research Question: Does Random Forest Improve Over the Complete Rule Baseline?

A. Mathematical Evaluation on Synthetic Data

No, mathematically it does not. On the synthetic operational dataset, the Complete Generator-Derived Rule Baseline achieves absolute perfection (MAE = 0.0000, R² = 1.0000, 100.00% ±1-day). The Random Forest Regressor achieves an MAE of 0.0815 days (≈ 1.96 hours) and a ±1-day accuracy of 97.20%. Thus, on purely deterministic simulated data, Random Forest introduces a minor statistical approximation error when fitting step functions and calendar tables.

B. Feature Information Asymmetry

The Complete Rule Baseline operates with the exact intake date (intake_date) and a hardcoded calendar of 8 statutory closure dates. Conversely, Random Forest was trained on Feature Set C, which contains only aggregated temporal signals: intake_day_of_week (0–5) and intake_month (1–12). Without the exact day of the month, Random Forest statistically learned to associate increased delays with April and December, but could not pinpoint exact non-working dates.

C. Operational Context & Deployment Value

Where ML Adds Defensible Value: In practical shop management, technicians use static base SLAs (the Base-Tier Baseline). Against this heuristic baseline, Random Forest delivers a massive 58.57% error reduction (from 0.1967 to 0.0815 days). More importantly, real-world shoe restoration is stochastic (technician backlog, drying times, material delays, and rework). A deterministic rule engine fails under real-world fluctuations; machine learning models adapt dynamically to live operational conditions.

Formal, Third-Person Scientific Presentation for Direct Manuscript Inclusion

Evaluation of Baseline Benchmarks and Machine Learning Models on the Simulated Operational Dataset (SOD). To evaluate the capability of predictive machine learning models to estimate service completion timelines, candidate algorithms were benchmarked against naive central tendencies and deterministic heuristic rules across the held-out test partition (N = 1,500) of the Simulated Operational Dataset (SOD). The prediction target was the continuous Received-to-Ready-for-Release turnaround duration measured in days. The evaluation protocol benchmarked seven models: a Mean-Duration Baseline, a Median-Duration Baseline, a Base-Tier Rule Baseline (representing static service-level agreements), a Complete Generator-Derived Rule Baseline (incorporating operational calendar closures), an Ordinary Least Squares Linear Regression model, a single Decision Tree Regressor, and the finalized Random Forest Regressor.

As summarized in Table 4.x, central tendency baselines exhibited substantial error. The Mean-Duration Baseline (MAE = 7.6391 days, R² = -0.0000) and Median-Duration Baseline (MAE = 7.3353 days, R² = -0.1458) achieved only 0.00% and 14.67% accuracy within a ±1-day tolerance, demonstrating that static central tendencies cannot accommodate the multi-tier operational distribution of footwear restoration services. The Linear Regression model demonstrated partial explanatory power (R² = 0.8472, MAE = 2.5097 days), but performed poorly because the shop's operational hierarchy follows discrete, dominant-tier step functions rather than additive linear relationships.

To thoroughly assess heuristic shop practices, two deterministic rule benchmarks were evaluated. The Base-Tier Rule Baseline implemented the shop's standard turnaround service tiers (10 days for basic cleaning and minor reglue, 20 days for unyellowing and minor restoration, 25 days for full reglue and color renewal) along with the 1-day rush override for eligible basic cleaning orders, but omitted calendar adjustments. This baseline achieved an MAE of 0.1967 days, an RMSE of 0.5825 days, and an R² of 0.9950. The average error of 0.1967 days corresponds exactly to the 295 rollover days accumulated across 240 test orders that landed on closed Sundays or statutory holiday periods. In contrast, the Complete Generator-Derived Rule Baseline, which incorporated both the service tier rules and full calendar closure adjustments using the order intake date, achieved perfect accuracy (MAE = 0.0000 days, RMSE = 0.0000 days, R² = 1.0000, and 100.00% ±1-day tolerance), confirming that the simulation engine operated deterministically.

The machine learning models demonstrated strong non-linear rule-learning capacity. The single Decision Tree Regressor achieved an MAE of 0.0773 days (≈ 1.86 hours), an RMSE of 0.4053 days, and an R² of 0.9976, with 97.33% ±1-day accuracy. The finalized Random Forest Regressor recorded an MAE of 0.0815 days (≈ 1.96 hours), an RMSE of 0.4042 days, an R² of 0.9976, a ±1-day tolerance of 97.20% (1,458/1,500), and reached 100.00% accuracy within a ±5-day window.

Comparative Value of the Finalized Random Forest Model. When evaluated against the Base-Tier Rule Baseline, the Random Forest model achieved a 58.57% reduction in mean absolute error (from 0.1967 to 0.0815 days). Because the model was trained with order intake day-of-week and intake month, it learned the calendar rollover mechanism statistically, successfully anticipating non-working days without requiring an explicit external calendar lookup table. However, when compared to the Complete Generator-Derived Rule Baseline, Random Forest does not yield an empirical improvement on the synthetic dataset, as the complete rule engine operates with zero error. The Random Forest model exhibits a slight approximation error (0.0815 days MAE) attributable to feature resolution: while the complete rule engine accesses exact calendar dates and specific holiday dates, Feature Set C provides only day-of-week and month indicators, requiring the model to infer holiday closures probabilistically.

Methodological Delimitation & Real-World Justification: The perfect fidelity of the Complete Rule Baseline is an artifact of the synthetic procedural generation process, which held technician throughput, queue backlogs, material stockouts, and drying conditions constant. In actual commercial deployment, footwear restoration is subject to significant stochastic variance that hardcoded deterministic rules cannot predict. While a complete rule engine is mathematically optimal on simulated rule-based data, a trained machine learning model provides superior utility in production by dynamically adjusting predictions based on multi-pair complexity, service combinations, and empirical operational backlogs. Prospective validation using unobserved real-world orders collected during live operations is necessary to evaluate the model's true empirical generalization.
