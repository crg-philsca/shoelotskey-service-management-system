Source Code Implementation & Sequencing Rules

Generator Implementation: backend/order_numbering.py:189-207 (next_canonical_order_id) & backend/main.py:4714-4718 (_live_canonical_order_number).

Canonical Format: ORD-YYYY-MM-DD-NNN (Regex: ^ORD-\d{4}-\d{2}-\d{2}-\d{3}$).

Sequencing & Collision Rule: Sequence NNN resets daily for each calendar intake date. It scans all existing order numbers with prefix ORD-YYYY-MM-DD- across both orders and historical_orders in PostgreSQL, finds the maximum existing sequence, and allocates max_seq + 1 zero-padded to 3 digits.

PostgreSQL Uniqueness Enforcement: orders.order_number carries a database-level UNIQUE constraint. The generator includes a collision loop ensuring candidate uniqueness before insertion.

Live Production Demonstration: On September 14, 2026, PostgreSQL already contains ORD-2026-09-14-001 (Juana Reyes) and ORD-2026-09-14-002 (Anna Karina). 5 Import Idempotency Guarantee

The import process is fully idempotent. If BATCH-HIST-SEP2026-001 is executed a second time, it will produce:
0 duplicate orders, 0 duplicate items, 0 duplicate payments, and 0 duplicate expenses.

Idempotency Enforcement Protocol:

  1. Batch Pre-Check: The script checks csv_import_batches for batch_id = 'BATCH-HIST-SEP2026-001'. If already marked COMPLETED, the entire batch run halts with a safe status report.
  2. Order Number Pre-Check: Every order insert checks orders.order_number uniqueness. If the candidate order number already exists, it is skipped.
  3. Business Signature Check: The script checks (customer_name, intake_date, grand_total). Any record matching an existing batch entry is flagged as ALREADY_IMPORTED and skipped.
  4. Expense Signature Check: Expenses check description LIKE '%[BATCH-HIST-SEP2026-001]%'. Existing expenses are skipped.
