In the current implementation, Shoelotskey SMS is strictly an internal intranet/web management system used exclusively by the owner and shop technicians. Customers must physically visit the Villamor shop or message staff via personal Facebook Messenger accounts to inquire about order status, causing repetitive verbal inquiries and staff interruptions during bench work.

Develop a decoupled, lightweight customer-facing Progressive Web App (PWA) allowing customers to log in using their mobile number with One-Time Password (OTP) verification via SMS. The portal enables clients to:

  • View real-time stage progress (e.g., Received $\rightarrow$ Cleaning in Progress $\rightarrow$ Curing $\rightarrow$ Ready for Pickup).

  • Authorize add-on services or repair recommendations digitally.

Prototype Deferred
Originating Context: Shop Staff Feedback & Counter Operations
Target ISO Characteristic: Performance Efficiency, Safety
Operational Priority: Medium (Counter Speed)
Target Deployment: Version 1.5 Update
Observed Limitation in Version 1.0:

While the digital search bar achieves an average retrieval time of 0.41 minutes (24.6 seconds), staff must still manually type the customer name or order number on the keyboard when a client presents their paper claim stub. 4. Domain 2: Machine Learning Retraining & Explainable AI (XAI)

RANK 4 Automated Weekly ML Retraining Pipeline with Drift Detection
Future Research
Evaluator Cited: Ken Carlo Javier (Table 24, Rank 4 - 20.0%)
Target ISO Characteristic: Maintainability, Reliability
Operational Priority: Critical for Long-Term AI Value
Target Deployment: Next Research Phase
Expert Comment (Ken Carlo Javier):

"Automated pipeline to retrain the ML model weekly with new historical data."

Technical Implementation Design:

In Version 1.0, the Random Forest model was trained on 119 validated historical orders. As the shop operates the digital system, new orders accumulate in the PostgreSQL database with authentic released_at timestamps. An automated retraining worker (using Celery or GitHub Actions cron) should be scheduled to:

  1. Query all completed orders where status = 'Claimed' and released_at IS NOT NULL.
  2. Calculate the pure bench duration: bench_turnaround_days = (released_at - created_at).
  3. Evaluate model drift against the holdout set; if the newly trained model achieves an MAE lower than 8.56 days, promote it to active production and archive the older model artifact with an audit log.

7. Domain 5: Enterprise Security & Backend API Hardening

RANK 4 Strict Defense-in-Depth API Validation & Payload Schema Enforcement
Implemented V1.1
Evaluator Cited: Ken Carlo Javier (Table 24, Rank 4 - 20.0%)
Target ISO Characteristic: Security, Reliability
Operational Priority: Critical for OWASP Compliance
Target Deployment: Version 1.1 (Active)
Expert Comment (Ken Carlo Javier):

"Backend API validation is overly permissive. While the UI correctly blocks empty fields, direct API testing shows it accepts empty or malformed payloads and assigns default values (e.g., 0.00 for totals) instead of rejecting them, lacking defense-in-depth. See ORD-2026-09-19-001 for example. Enforce strict backend validation to reject incomplete payloads at the API level."

Remediation Status:

This vulnerability was confirmed and resolved in the active codebase by replacing untyped Dict[str, Any] request bodies with strict Pydantic schemas (OrderCreateSchema) that validate phone numbers, non-zero items, positive prices, and non-empty customer names before accepting requests.

Implemented V1.1
Evaluator Cited: Ken Carlo Javier (Table 24, Rank 4 - 20.0%)
Target ISO Characteristic: Interaction Capability, Usability
Operational Priority: High (Shop Floor Usability)
Target Deployment: Version 1.1 (Active)
Expert Comment (Ken Carlo Javier):

"Enhance the interface to comply with WCAG standards. Improve color contrast (the current gray text is difficult to read) and ensure proper font sizing for better readability."

Remediation Status:

In the original prototype, secondary labels used text-gray-400 (#9CA3AF), yielding a contrast ratio of only 2.14:1 against white backgrounds (failing WCAG 4.5:1 AA). The active codebase updated these styles to text-slate-600 (#475569, contrast ratio 7.0:1) and standardized all micro-fonts to at least text-xs (12px), ensuring readability on shop tablets under varying lighting.
