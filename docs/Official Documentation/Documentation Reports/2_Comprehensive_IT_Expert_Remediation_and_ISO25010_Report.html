3. Database Schema Design, 3NF Normalization & Backup Operations

The relational database schema is modeled in PostgreSQL using SQLAlchemy ORM. It strictly follows the Third Normal Form (3NF) to eliminate data anomalies, ensure data integrity, and support scalable transaction processing.

Third Normal Form (3NF) Formal Verification

Normalization Level Technical Requirement Implementation Verification in Shoelotskey Database Status
First Normal Form (1NF) - All table attributes must contain atomic (indivisible) values.
- Each record must have a unique Primary Key.
- No repeating groups or multivalued columns. 		All tables define unambiguous primary keys (`id`, `order_id`, `user_id`). Repeating items within a job order (multiple shoe pairs, multiple services) are properly extracted into dedicated relational tables (`order_items`, `order_item_addons`) rather than stored as comma-separated strings. ✓ 100% 1NF Compliant
Second Normal Form (2NF) - Must be in 1NF.
- All non-key attributes must be fully functionally dependent on the entire primary key (no partial dependencies). 		Single-attribute surrogate keys (`id`) are utilized across all core entities. In junction tables such as `order_item_addons`, addon attributes depend directly on the primary key, eliminating partial functional dependencies. ✓ 100% 2NF Compliant
Third Normal Form (3NF) - Must be in 2NF.
- No transitive dependencies (non-key attributes must depend only on the primary key, not on another non-key attribute). 		Customer contact information is strictly isolated in the `customers` table (`customer_id`); `job_orders` references `customer_id` via foreign key without duplicating customer phone or address columns. Service prices and categories depend strictly on `service_id` in `services`, preventing transitive anomalies. ✓ 100% 3NF Compliant
