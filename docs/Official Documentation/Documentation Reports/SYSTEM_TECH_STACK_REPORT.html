Historical & ML Data 9 tables HistoricalOrder, HistoricalItem, HistoricalItemService, HistoricalImage, HistoricalPrediction, EtlImportHistory, CsvImportBatch, HistoricalReconciliationConflict, Delivery Separate physical tables archiving 714 paper receipts (Jan 2024–Jan 2026) for ML retraining.
Research Benchmarking 4 tables ResearchTestRun, ResearchMeasurement, StatusLog, ShippingPreference Empirical timing proofs storage (retrieval times, report generation times, MAE runs).
Production Fail-Closed Guard (P0-5): In cloud deployment, the database connection strictly refuses silent SQLite fallback if PostgreSQL is unreachable. Silent fallback to SQLite in production would cause split-brain data loss across staff registers. Local SQLite fallback is restricted exclusively to local development and offline defense presentation continuity.

🔒 OWASP Top 10 Security Architecture & Codebase Implementation
OWASP Category Vulnerability Prevented Engineered Control Mechanism Codebase Verification Proof
A01:2021 — Broken Access Control Unauthorized privilege escalation (Staff accessing Owner financials). JWT tokens with embedded role claims validated on 65 backend endpoints via require_role and require_admin decorators. Client-side route guards. backend/auth_utils.py & src/app/routes.tsx
A02:2021 — Cryptographic Failures Credential theft via database breaches. Passwords hashed with native Bcrypt using 12 cryptographic salt rounds. Plaintext passwords never stored or logged. HTTPS transport encryption. backend/auth_utils.py line 45
A03:2021 — Injection SQL injection manipulating database queries. 100% of database interactions handled via SQLAlchemy ORM parameterized queries. Zero raw string interpolation. Pydantic schema type validation. backend/database.py & backend/routers/*
A05:2021 — Security Misconfiguration Database exposure or accidental SQLite downgrade. Production environment locks down debug flags, enforces CORS domain allowlists, and enforces fail-closed behavior on database disconnect. backend/main.py lines 35–52
A07:2021 — Identification & Authentication Brute-force credential guessing attacks. 3-Attempt Account Lockout: 3 consecutive failed logins freeze the account for 15 minutes. 30-Minute Idle Session Expiry: Automatic logout on client inactivity. backend/api/auth.py & src/app/context/AuthContext.tsx

🛡 Architectural Justification & Panel Defense Q&A
Panel Question: "Why did you choose FastAPI over traditional Python frameworks like Django or Flask?"
Candidate Defense: "We selected FastAPI for three decisive engineering reasons: First, FastAPI is built natively on ASGI (via Starlette and Uvicorn), providing asynchronous non-blocking I/O that easily handles high concurrency when multiple counter staff access the system simultaneously. Second, it enforces strict type hints and uses Pydantic v2 for data validation, automatically rejecting malformed payloads and auto-generating OpenAPI documentation. Third, because our machine learning and OCR modules are written in Python, FastAPI allows our predictive models to run natively in-process without requiring separate microservice serialization layers."
Panel Question: "Why did you select React + Vite instead of a Server-Side Rendered (SSR) framework like Next.js?"
Candidate Defense: "Shoelotskey's operations are predominantly dynamic, internal workflow management rather than public search-engine-indexed content. A Single-Page Application (SPA) using React 18 and Vite provides instantaneous page transitions without full-page reloads, caching active job order forms locally in memory. This delivers a frictionless user experience that directly supported our high Technology Acceptance Model score (TAM = 3.88). Vite also provided instantaneous Hot Module Replacement and optimized production bundle compilation."
Panel Question: "Why did you use Random Forest instead of Deep Learning or XGBoost for your duration prediction?"
Candidate Defense: "Our historical dataset comprises 119 validated service records across 6 monthly intake volumes. Deep neural networks require tens of thousands of rows to generalize without severe overfitting. Random Forest is mathematically suited for small-to-medium tabular datasets: its bootstrap aggregation (bagging) of 150 decision trees resists outliers, requires minimal hyperparameter tuning, and provides direct feature importance interpretability, which proved that service type and pair count were the primary drivers of turnaround duration."
Panel Question: "Why PostgreSQL instead of NoSQL like MongoDB?"
Candidate Defense: "Shoelotskey's operations involve strict relational business rules: an order belongs to a customer, contains multiple items, maps to specific service prices, consumes inventory supplies, and logs payments. PostgreSQL guarantees ACID compliance and referential integrity via foreign key cascades, preventing orphaned records. In addition, PostgreSQL supports row-level locking (with_for_update) to prevent race conditions during concurrent inventory stock depletions."
