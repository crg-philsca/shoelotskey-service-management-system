05. General System Q&A

Why this project? What problem does the system solve? ▼

Concise Answer: Shoelotskey suffered from inefficient manual logbooks resulting in 15-30 minute customer record retrievals, subjective turnaround dates causing missed deadlines, and a complete lack of business analytics.

Deeper Answer: The system solves these three operational gaps by centralizing records in PostgreSQL, calculating objective release dates using defined business rules supplemented by machine learning, and aggregating real-time financial tracking on the dashboard.

Why web-based instead of a mobile app? ▼

A web-based SPA ensures compatibility across the shop's existing devices (counter laptop and staff mobile phones) without the overhead of iOS/Android app store approval. It's cross-platform by default and allows instantaneous deployment updates.

What happens when the internet fails? ▼

The system is entirely cloud-hosted on Heroku. If the internet fails, the system is inaccessible. We do not claim offline functionality. The shop must revert to emergency manual ticketing and transcribe the data once connectivity is restored.

06. Machine Learning Q&A

Why Random Forest Regressor? ▼

Concise Answer: Random Forest handles non-linear relationships and avoids overfitting on small datasets better than neural networks or linear regression.

Deeper Answer: Shoe repair turnaround isn't strictly linear (e.g. drying times overlap). Neural networks require thousands of records, which we don't have. Random Forest (with n=150 estimators and max_depth=10) provides robust decision boundary averaging suitable for our 18-feature vector.

Why only 35 ML records? Did you achieve the 85% accuracy target? ▼

Concise Answer: The shop provided 676 scanned logbooks, but after strict human validation, only 48 records were structurally sound, resulting in 35 eligible records. We did not target 85% because this is a regression problem, not classification.

Deeper Answer: Regression is measured by MAE and RMSE. Our MAE is 7.61 days. The high variance is due to the small dataset and the fact that our target label is "Claimed Date", which includes customer pickup delays. This proves why our ML is strictly an advisory forecast, while Business Rules act as the official commitment.

What exactly does ML predict? ▼

It predicts CompletionDays (the number of days from order receipt to claim). It uses 18 features (e.g., total_pairs, full_reglue_qty, priority_encoded, yellowing_count).

07. Architecture & Security Q&A

Why React and FastAPI? ▼

React SPA provides a snappy, instant POS-like interface for the counter staff. FastAPI is a modern, high-performance async Python framework that allowed us to seamlessly integrate our scikit-learn Machine Learning model without language-bridging workarounds.

How is security enforced? How do you stop SQL Injection? ▼

Authentication: Passwords are hashed via bcrypt. We use stateless JSON Web Tokens (JWT) stored in HTTP headers.
Authorization: FastAPI dependencies check the JWT role claim to block Staff from Owner routes.
SQL Injection: 100% of queries use SQLAlchemy ORM, which automatically parameterizes all SQL statements.

What happens if a user tries to brute force a password? ▼

The system enforces a 3-attempt account lockout policy. After 3 failed logins, the account is locked for 15 minutes. The backend returns a 403 Forbidden before computing the bcrypt hash, preventing server CPU starvation.

08. Database & 3NF Q&A

Why PostgreSQL and Heroku? ▼

PostgreSQL provides robust ACID compliance, JSONB support, and excellent transactional integrity. Heroku provides a zero-ops PaaS environment where the database is managed with automated snapshots.

Prove that your database is in Third Normal Form (3NF). ▼

1NF: All values are atomic; no repeating arrays. Multi-pair orders are isolated in order_shoes junction tables.
2NF: All tables use single-column surrogate primary keys (id), eliminating partial dependencies.
3NF: No transitive dependencies. For example, job_orders holds customer_id but does not duplicate the customer's phone number or address.

09. ISO 25010 & TAM Q&A

Why ISO/IEC 25010 instead of 9126? Why 9 characteristics? ▼

ISO/IEC 25010:2023 is the modern, current international standard for software quality, replacing the obsolete 9126. It adds modern concerns like Security and Compatibility. We evaluated all 9 characteristics using a 45-statement instrument to ensure comprehensive coverage.

Why TAM? Why Owner + 2 Staff? ▼

TAM (Technology Acceptance Model) is the academic standard for measuring whether users will actually adopt a new system based on 4 constructs: Perceived Usefulness, Perceived Ease of Use, Behavioral Intention, and Actual System Use. Shoelotskey operates with 1 Owner and 2 Staff members. We must evaluate the actual operational population, not fabricate 5 employees.
