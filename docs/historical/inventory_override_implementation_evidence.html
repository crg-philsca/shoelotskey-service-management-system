1. Root Cause Analysis of Previous Limitation

In OrderDetailModal.tsx, the action controls were erroneously restricted by strict equality to isForRelease: 

// PREVIOUS ERRONEOUS RESTRICTIONS:
const isForRelease = normalizedOrderStatus === 'for-release';
const canAddRetail = isForRelease && !isClaimed;
const canAddMaterial = isItemForRelease && !isItemClaimed && canUserUseStock;
// In JSX:
{order && materialModalTarget && (isForRelease && !isClaimed) && ( <AddMaterialModal ... /> )}

Because isForRelease strictly required the status to be For Release, orders in new-order and on-going were completely hidden from adding materials or retail products!

2. Operational Workflow Logic (Shoe Restoration Business)

  • • New Order (Intake): Material usage allowed for pre-inspection, initial spot test, or intake prep. Retail allowed because customers frequently purchase shoelaces or cleaner at drop-off.
  • • On-going (Active Workshop Servicing): PRIMARY WORKSTAGE. Technicians actively clean, reglue, paint, stitch, and condition shoes. It is essential that materials can be consumed and recorded here!
  • • For Release (Ready for Pickup): Allowed for final buffing, deodorizer spray, and impulse counter retail purchases at pickup.
  • • Claimed (Completed & Settled): STRICTLY LOCKED. The customer has paid in full, received their claim slip/official receipt, and taken their shoes. Financial totals and material records are closed.
