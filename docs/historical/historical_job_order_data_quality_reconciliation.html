3. Release Date Semantics Code Trace & Correction

  • Frontend Label: Dashboard column header currently reads Release Date.
  • Frontend Property: Bound to order.predictedCompletionDate.
  • API Serializer: Maps from SQLAlchemy Order.expected_at.
  • Root Cause of Same-Day Date: The historical import script stored a derived storage anchor (order_date + 18:00:00) to satisfy the NOT NULL constraint on Order.expected_at. When formatted as MM/dd/yy, it produced identical Order Date and Release Date (e.g. 09/07/26).
  • Proposed UI Correction:
    1. Rename table header to EXPECTED RELEASE when viewing New Orders.
    2. For historical orders where expected date is solely a derived storage anchor, display — (or Not documented).
    3. Never fallback to Order Date as a surrogate release date.

4. Status & Lifecycle Integrity (22 Quarantined DSMR Claims)

All 54 historical orders currently maintain status_id = 1 (New Order) with released_at = NULL and claimed_at = NULL. This conservative policy was established to prevent manufactured timestamps. The 22 DSMR Claim transactions remain quarantined in the evidence layer. To prevent fabricating midnight pickup timestamps (00:00:00), claim linkages will remain in evidence records until explicit date-only historical outcome presentation is authorized.
