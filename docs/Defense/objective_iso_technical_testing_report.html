1. Executive Summary

This document provides the formal, reproducible technical testing evidence for the capstone manuscript: “A Web-Based Service Management System with Data Analytics Using Machine Learning Algorithms for Shoelotskey Villamor–Pasay.”

📋 Academic Evaluation Context

In response to the academic evaluator’s observation that subjective questionnaire responses (e.g., Likert-scale survey data) cannot serve as objective proof of ISO/IEC 25010 software quality compliance, the researchers formulated a formal technical testing harness. Every value, latency figure, HTTP status code, and pass/fail determination reported herein stems directly from physical executions against the live application stack (FastAPI 0.135.1, Uvicorn 0.42.0, SQLAlchemy 2.0.48, SQLite 3.50.4, and Playwright 1.63.0 browser automation).

Across 10 predefined technical evaluation categories, a total of 306 individual technical trials were systematically performed, recorded, and preserved into raw CSV datasets. Zero results were simulated, fabricated, or mathematically estimated. Where testing was infeasible due to platform boundaries (specifically Mozilla Firefox binary absence and Apple Safari platform exclusivity), results are explicitly disclosed as NOT TESTED – INSUFFICIENT EVIDENCE.

2. Purpose of Objective Testing & Research Integrity Rules

The objective testing suite evaluates six core quality characteristics established in the ISO/IEC 25010:2011 System and Software Quality Model:

  • Performance Efficiency (Time Behaviour & Capacity): High-resolution latency profiling across 6 endpoints and staged concurrency workloads (1 to 20 threads).
  • Reliability (Maturity, Fault Tolerance, Recoverability): Relational database constraint validation, error recovery without crashing, automated backup archive generation and isolated restoration parity, and 30-cycle repeated workflow durability.
  • Compatibility (Co-existence & Interoperability): Multi-browser end-to-end user workflow execution across verified local browser engines.
  • Security (Confidentiality, Authenticity, Non-repudiation): Granular Role-Based Access Control (RBAC) boundary enforcement and brute-force lockout defenses.
  • Functional Suitability & Safety: Dual-tier client/server input validation, payload boundary checks, and injection defense.
⚠️ Non-Certification Disclaimer

In accordance with scientific integrity standards, this technical evaluation demonstrates measurable empirical conformance to specific technical quality requirements within a controlled evaluation environment. This report does NOT claim formal ISO/IEC 25010 certification or commercial OWASP certification.

The following technical boundaries are transparently reported to preserve academic truthfulness:

  • Mozilla Firefox (Gecko Engine): The host evaluation workstation did not have a local Firefox binary installed. In accordance with anti-fabrication rules, cross-browser compatibility for Firefox was marked NOT TESTED – INSUFFICIENT EVIDENCE.

9. Manuscript-Ready Narrative Interpretation

📖 Recommended Academic Text for Chapter 4

To substantiate the ISO/IEC 25010 evaluation with empirical technical evidence, the researchers subjected the Shoelotskey Service Management System to a comprehensive suite of objective automated tests. Rather than relying solely on subjective questionnaire responses, 306 empirical trials were executed across ten functional and technical domains.

In evaluating Performance Efficiency, the system exhibited robust time behaviour under repeated measurement (n=30 trials per operation). Operational endpoints achieved sub-second response times, ranging from a mean of 17.82 ± 17.90 ms for Random Forest machine learning turnaround predictions to 128.47 ± 94.57 ms for job order data retrieval. User authentication averaged 517.10 ± 58.39 ms, reflecting the intentional computational cost of salted Bcrypt password hashing. Under staged concurrency testing (1 to 20 concurrent threads), the application sustained a 100.0% HTTP 200 completion rate without database lock collisions or server-side internal errors.

Assessment of Reliability demonstrated fault tolerance and recoverability. Relational integrity audits confirmed that primary key uniqueness, foreign key constraints, and transactional atomicity were consistently enforced (10/10 checks passed, 100.0%). The automated backup engine successfully packaged 10,840 relational records across 29 tables into a verified tar.gz archive with cryptographic SHA-256 verification, and achieved 100.0% table and record parity upon restoration into an isolated database. Furthermore, in repeated end-to-end operational testing across 30 consecutive service cycles, the system recorded a 100.0% success rate (30/30 passed) with a mean lifecycle execution time of 315.51 ms.

In terms of Security and Functional Suitability, granular Role-Based Access Control (RBAC) prevented unauthorized access across all tested routes (HTTP 401/403 enforced), brute-force lockout triggered exactly after three failed attempts with a 15-minute lockout duration, and all 13 malicious or malformed input vectors (including XSS, SQL injection, negative financial values, and buffer overflow attempts) were rejected at the API layer without database mutation. Cross-browser testing confirmed full functional rendering on Chromium-based engines (Google Chrome and Microsoft Edge), while Gecko and WebKit engines were documented as untested due to workstation platform boundaries. These objective findings provide empirical evidence supporting the system's operational readiness.
