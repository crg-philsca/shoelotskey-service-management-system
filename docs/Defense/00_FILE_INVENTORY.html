4. Priority Conflicts & Semantic Inconsistencies to Audit

⚡
Key Inconsistencies Flagged for Checkpoints 1–5 Investigation:
  • Chapter 1 vs Target Ground Truth: Chapter 1 repeatedly uses "service completion date estimation" in problem statements and objectives, while Chapter 3 and empirical datasets confirm that historical paper receipts contained no technician completion timestamps. The actual historical target is turnaround_duration = claimed_date − date_received. Chapter 1 must be harmonized to "advisory predicted release date / turnaround duration" rather than actual service completion time.
  • Slide 11 vs Slide 15 Sample Size Discrepancy: Presentation Slide 11 labels the evaluation results a "10-record test sample", while Slide 15 cites the exact same figures (MAE 8.50, RMSE 10.11, R² 0.129) as a "26-record test set". The locked holdout dataset contains exactly 26 records (January 2026); 10 records represents only an illustrative preview table. Both slides must align on the authoritative 26-record locked evaluation.
  • Automated Retraining vs Controlled Architecture: Previous documentation reports suggested "Automated Weekly ML Retraining" with auto-promotion if MAE improves. Code inspection shows the production model is statically loaded from backend/completion_model.pkl. In academic defense terms, uncontrolled automatic retraining on unvalidated operational data introduces severe drift and leakage risk. The true system architecture is controlled manual retraining with validation.
  • Reliability Dimension Narrative Contradiction: In Chapter 4 (p. 127) and Chapter 5 (pp. 141, 149), narrative text claims Reliability scored 3.76 (SD 0.31), whereas Table 13 and raw evaluator forms prove Reliability scored 3.72 (SD 0.49).
  • Table Cross-Reference Error (p. 144): Chapter 4 narrative directs readers to "suggestions and comments presented in Table 24", but the actual IT Expert Suggestions table is Table 25.
